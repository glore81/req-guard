# Техническое задание
## Досрочное погашение потребительского кредита в мобильном банке

---

## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
|---|---|
| Наименование задачи | Досрочное погашение потребительского кредита в мобильном банке |
| Продукт | Потребительский кредит (кредит наличными) |
| Бизнес-процесс | Погашение кредита: частичное и полное досрочное погашение с выбором способа пересчёта графика |
| Тип работы | Новая функциональность (доработка мобильного приложения и кредитного модуля АБС) |
| Влияние на ИС | Мобильное приложение (iOS/Android), кредитный модуль АБС, сервис расчёта графиков, сервис платежей, интернет-банк (веб) |

### Цели

1. Предоставить клиенту возможность самостоятельно оформить досрочное погашение потребительского кредита в мобильном банке без визита в отделение.
2. Обеспечить выбор способа пересчёта графика: уменьшение срока кредита или уменьшение ежемесячного платежа.
3. Автоматизировать пересчёт графика платежей и отображение нового графика клиенту до подтверждения операции.
4. Сократить количество обращений в контактный центр по вопросам досрочного погашения.
5. Обеспечить корректное отражение операции в учётной системе банка в день её проведения.

### Архитектура решения

Решение реализуется как расширение существующего мобильного банка и кредитного модуля АБС.

Компоненты:
- **Мобильное приложение** — экран «Мой кредит», сценарий досрочного погашения, отображение текущего и нового графика.
- **API-шлюз мобильного банка** — маршрутизация запросов, авторизация клиента.
- **Сервис кредитов (Credit Service)** — получение параметров кредита, инициирование досрочного погашения, передача команды в АБС.
- **Сервис расчёта графиков (Schedule Calculation Service)** — расчёт нового графика при выбранном способе пересчёта.
- **Кредитный модуль АБС** — проведение операции, фиксация нового графика, бухгалтерские проводки.
- **Сервис платежей** — списание суммы досрочного погашения с текущего счёта клиента.

Взаимодействие компонентов — синхронное по REST, с фиксацией результата операции в АБС.

### Дизайн процесса UI

Экран «Мой кредит» → кнопка «Досрочное погашение».

Шаги сценария:
1. **Экран 1. Параметры кредита.** Отображаются: номер договора, текущая сумма задолженности, дата ближайшего платежа, сумма ежемесячного платежа, оставшийся срок.
2. **Экран 2. Сумма погашения.** Клиент выбирает тип: «Частичное» или «Полное». Для частичного вводит сумму. Отображается подсказка о минимально допустимой сумме. Для полного сумма подставляется автоматически.
3. **Экран 3. Способ пересчёта.** Клиент выбирает: «Уменьшить срок» или «Уменьшить платёж». Для полного погашения шаг пропускается.
4. **Экран 4. Новый график.** Отображается предварительный новый график платежей (первые 12 строк и итог). Клиент подтверждает операцию.
5. **Экран 5. Результат.** Отображается статус операции, номер операции, дата вступления в силу нового графика.

Для подтверждения операции используется существующий механизм подтверждения мобильного банка.

### BPMN схема процесса

```
[Клиент] Открывает кредит
   → [МП] Запрос параметров кредита → [Credit Service] → [АБС]
   → [МП] Отображение параметров
   → [Клиент] Выбирает тип и сумму погашения
   → [МП] Запрос предварительного графика → [Schedule Calculation Service]
   → [МП] Отображение нового графика
   → [Клиент] Подтверждает операцию
   → [МП] Отправка команды досрочного погашения → [Credit Service]
   → [Credit Service] Проверка доступности суммы на счёте
        ├─ недостаточно средств → [МП] Сообщение об ошибке
        └─ достаточно средств → [Сервис платежей] Списание суммы
              → [АБС] Проведение операции, фиксация нового графика
              → [Credit Service] Возврат результата
              → [МП] Экран результата
```

### Функциональные требования

**Ф-1.** Мобильное приложение должно отображать на экране «Мой кредит» актуальные параметры кредита: номер договора, сумму текущей задолженности, дату и сумму ближайшего платежа, оставшийся срок кредита.

**Ф-2.** Клиент должен иметь возможность выбрать тип досрочного погашения: частичное или полное. При полном погашении сумма рассчитывается системой автоматически.

**Ф-3.** При частичном досрочном погашении клиент вводит сумму погашения. Система должна проверить, что сумма не меньше минимально допустимой суммы частичного погашения и не превышает сумму текущей задолженности.

**Ф-4.** При частичном досрочном погашении клиент выбирает способ пересчёта графика: уменьшение срока кредита или уменьшение ежемесячного платежа. Выбранный способ должен быть передан в кредитный модуль АБС.

**Ф-5.** До подтверждения операции мобильное приложение должно отобразить клиенту предварительный новый график платежей, рассчитанный для выбранного способа пересчёта.

**Ф-6.** После успешного проведения операции досрочного погашения кредитный модуль АБС должен зафиксировать новый график платежей и мобильное приложение должно отобразить клиенту результат операции с номером операции и датой вступления в силу нового графика.

### Sequence Diagram (текстом)

```
Клиент -> МП: Открыть экран «Мой кредит»
МП -> Credit Service: GET /credits/{creditId}
Credit Service -> АБС: Запрос параметров кредита
АБС --> Credit Service: Параметры кредита
Credit Service --> МП: Параметры кредита
МП --> Клиент: Отображение параметров

Клиент -> МП: Выбрать тип, сумму, способ пересчёта
МП -> Schedule Calculation Service: POST /schedule/preview
Schedule Calculation Service --> МП: Предварительный график
МП --> Клиент: Отображение нового графика

Клиент -> МП: Подтвердить операцию
МП -> Credit Service: POST /credits/{creditId}/early-repayment
Credit Service -> Сервис платежей: Списание суммы
Сервис платежей --> Credit Service: Результат списания
Credit Service -> АБС: Проведение досрочного погашения
АБС --> Credit Service: Номер операции, новый график
Credit Service --> МП: Результат операции
МП --> Клиент: Экран результата
```

### Нефункциональные требования

- Время отклика экрана «Мой кредит» — не более 3 секунд при штатной нагрузке.
- Время расчёта предварительного графика — не более 5 секунд.
- Операция досрочного погашения должна быть доступна в мобильном банке круглосуточно, за исключением технологических перерывов АБС.
- Мобильное приложение должно поддерживать iOS и Android актуальных версий, поддерживаемых банком.
- Все операции досрочного погашения должны протоколироваться в журнале операций с сохранением идентификатора клиента, суммы и способа пересчёта.
- Интерфейс должен соответствовать действующему гайдлайну мобильного банка.

### Требования к данным

- Сумма текущей задолженности, сумма досрочного погашения, сумма ежемесячного платежа хранятся с точностью до копейки (2 знака после запятой).
- Тип досрочного погашения: `PARTIAL` (частичное) или `FULL` (полное).
- Способ пересчёта графика: `REDUCE_TERM` (уменьшение срока) или `REDUCE_PAYMENT` (уменьшение платежа). Для полного погашения поле не заполняется.
- Журнал операций досрочного погашения должен содержать: идентификатор операции, идентификатор кредита, дату операции, сумму, тип погашения, способ пересчёта, статус.
- Новый график платежей должен храниться с привязкой к номеру операции досрочного погашения.

### Требования к интеграции

- Интеграция мобильного приложения с Credit Service — синхронный REST-вызов, таймаут 10 секунд.
- Интеграция Credit Service с сервисом расчёта графиков — синхронный вызов, таймаут 5 секунд.
- Интеграция Credit Service с сервисом платежей — синхронный вызов списания, таймаут 15 секунд.
- Интеграция Credit Service с кредитным модулем АБС — синхронный вызов проведения операции, таймаут 30 секунд.
- При недоступности сервиса расчёта графиков операция досрочного погашения не должна проводиться, клиенту должно отображаться сообщение о временной недоступности.

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
|---|---|---|
| Клиент имеет действующий потребительский кредит с текущей задолженностью 150 000 руб. | Клиент выбирает частичное погашение на сумму 50 000 руб. и способ «Уменьшить срок» | Операция проведена, кредит действующий, новый график зафиксирован в АБС и отображён клиенту |
| Клиент имеет действующий потребительский кредит | Клиент выбирает частичное погашение на сумму 30 000 руб. и способ «Уменьшить платёж» | Ежемесячный платёж в новом графике меньше, чем в предыдущем, срок кредита не изменён |
| Клиент имеет действующий потребительский кредит с текущей задолженностью 80 000 руб. | Клиент выбирает полное погашение | Операция проведена на сумму текущей задолженности, кредит закрыт |
| Клиент имеет действующий потребительский кредит | Клиент вводит сумму частичного погашения меньше минимально допустимой | Система отображает сообщение об ошибке, операция не проводится |

## Часть B. REST API

### Общие параметры

| Параметр | Значение |
|---|---|
| Description | Метод оформления досрочного погашения потребительского кредита |
| REST type | POST |
| Authorization | Bearer-токен клиента (OAuth 2.0) |
| Controller | `EarlyRepaymentController` |
| Request URL для Dev | `https://dev.mobile-bank.local/api/v1/credits/{creditId}/early-repayment` |
| Request URL для Prod | `https://mobile-bank.ru/api/v1/credits/{creditId}/early-repayment` |
| Author | Иванов А.А., бизнес-аналитик |
| Developer | Петров С.С., разработчик |

### Логика работы метода

1. Метод принимает идентификатор кредита, сумму погашения, тип погашения и способ пересчёта.
2. Выполняется авторизация клиента и проверка, что кредит принадлежит клиенту и является действующим.
3. Выполняется валидация суммы: сумма должна быть больше нуля и не превышать сумму текущей задолженности.
4. Для частичного погашения проверяется, что способ пересчёта указан и входит в допустимое множество значений.
5. Выполняется списание средств и инициируется проведение операции в кредитном модуле АБС с фиксацией нового графика.
6. Метод возвращает результат операции, сумму списания и, при успехе, обновлённый график платежей.

### Особые правила

1. При полном погашении поле `recalculationType` игнорируется, даже если передано.
2. Если сумма погашения равна сумме текущей задолженности, операция трактуется как полное погашение независимо от переданного типа.
3. Повторный вызов метода с тем же `operationId` в течение 24 часов возвращает результат первой операции без повторного списания.

### Параметры запроса

| Parameter | Format | Size | Mandatory | Logic | Description |
|---|---|---|---|---|---|
| creditId | string | 36 | Да | UUID кредита | Идентификатор кредита |
| amount | decimal | 15.2 | Да | Больше 0 | Сумма досрочного погашения |
| repaymentType | string | 10 | Да | `PARTIAL` / `FULL` | Тип погашения |
| recalculationType | string | 20 | Нет | `REDUCE_TERM` / `REDUCE_PAYMENT` | Способ пересчёта графика |
| operationId | string | 36 | Да | UUID операции | Идентификатор операции для идемпотентности |

### Ответ

| Parameter | Format | Logic | Description |
|---|---|---|---|
| operationId | string | UUID | Идентификатор операции |
| status | string | `SUCCESS` / `PENDING_RECALC` / `ERROR` | Статус операции |
| chargedAmount | decimal | Больше 0 | Сумма списания |
| newSchedule | array | Список платежей | Обновлённый график платежей |
| message | string | Текст | Сообщение для клиента |

### Статусы

- **200 OK** — операция выполнена успешно, график пересчитан.
- **202 Accepted** — операция принята, пересчёт графика отложен (сервис расчёта графиков недоступен), статус `PENDING_RECALC`.
- **400 Bad Request** — ошибка валидации параметров запроса.
- **403 Forbidden** — кредит не принадлежит клиенту или не является действующим.
- **409 Conflict** — операция с данным `operationId` уже выполнена с другим результатом.
- **500 Internal Server Error** — внутренняя ошибка системы.
